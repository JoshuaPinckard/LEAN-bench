## Where the tapes diverge and why

### 1. Exit execution basis (ref2 vs refs 0/1) — first observable split
First trade: all three BUY 2021-06-15; refs 0/1 SELL 2021-07-08, ref2 SELL 2021-07-12.
- refs 0/1 evaluate stop/take intrabar: `low[0] <= stop`, `high[0] >= take`.
- ref2 evaluates all exits on close: `close <= stop`, `close >= take` (its ASSUMPTIONS: "All exit conditions ... are evaluated against the bar's close price").

Spec text: "**Place a stop-loss slightly below the second bottom (for example, 0.5% lower)**" and "**Close the position upon reaching a take-profit of 2:1**". Neither sentence pins whether "reaching" means an intrabar touch (resting-order semantics) or a close beyond the level; the stop distance itself is hedged ("slightly ... for example"), i.e. explicitly non-binding. The take-profit was hit intrabar days before the close crossed it, producing the 07-08 vs 07-12 split. Class: `unpinned-exit`.

### 2. Pattern detection scope / persistence (ref0 vs ref1) — same exit model, different entries
Both opus refs use identical 5-bar fractal pivots, close-cross breakout, and intrabar exits, yet diverge at the second entry (ref0 BUY 2023-03-21 vs ref1 BUY 2023-12-14) because they answered three questions the spec never asks:
- **Which lows pair up.** ref0 pairs only *adjacent* confirmed pivot lows (`pivot_lows[-2]` with the new one); ref1 scans *all* earlier pivot lows for a compatible first bottom. Spec: "**two consecutive lows at approximately the same level, separated by an intermediate peak**" — "consecutive" describes the pattern's visual shape, not an adjacency rule over detected pivots, and does not settle this.
- **Pattern persistence.** ref0 arms a pattern and keeps it "valid until a breakout entry occurs or a newer valid Double Bottom replaces it" (its ASSUMPTIONS); ref1 recomputes per bar with the latest pivot low as the mandatory second bottom, so an intervening new pivot low can silently kill a setup ref0 still holds armed. Spec gives no expiry/invalidation rule for a formed-but-unbroken pattern.
- **Pivot tie handling.** ref0 disqualifies a pivot only on a *strictly* lower/higher neighbor; ref1 disqualifies on ties (`<=`/`>=`). The spec never defines how "the first low", "an intermediate peak", or "the second low" are detected at all — no pivot window, no strictness, no Low-vs-Close basis.

Class: `unpinned-entry-trigger`.

### 3. Search breadth (ref2 vs both) — 10 trades vs 4–5
ref2 re-scans a 200-bar lookback every bar over *every* combination of local minima and maxima (triple loop b2/nl/b1), taking the first valid triple; refs 0/1 only ever consider patterns anchored at the newest pivot low. The spec bounds the gap from below ("**at least 10 candles pass between the two bottoms**") but never bounds the pattern's age or span, never says whether the neckline is *the highest* interior peak (refs 0/1: max; ref2: first qualifying local max), and never restricts how many candidate patterns may be live. ref2's broader search plus close-based exits yields 10 trades vs 4–5. Classes: `unpinned-entry-trigger` (search scope, neckline selection), `unpinned-exit` (holding-period differences compound).

### 4. Minor: tolerance denominator
"**no more than 1% lower or higher**" — refs 0/1 compute `abs(l2-l1)/l1` (first bottom as base); ref2 uses `abs(l1-l2)/max(l1,l2)`. The spec names no base for the percentage. Subsumed under `unpinned-entry-trigger`.
