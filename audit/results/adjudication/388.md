## Genuineness check (all three codes read line-by-line)

All three independently implement the spec's stated rules — this is not a
trivially-always-true rule:

- **Entry long** — spec: *"Go LONG when Williams %R crosses up through -80
  (yesterday/previous bar <= -80 and current bar > -80) AND Momentum > 0"*.
  All three: `wr[-1] <= -80 and wr[0] > -80 and mom[0] > 0`.
- **Entry short** — spec: *"Go SHORT when Williams %R crosses down through -20
  (previous bar >= -20 and current bar < -20) AND Momentum < 0"*.
  All three: `wr[-1] >= -20 and wr[0] < -20 and mom[0] < 0`.
- **Indicators** — spec: *"Use built-in Backtrader indicators (WilliamsR, Momentum,
  ATR)"* with *"period=14"* for each. All three: `bt.indicators.WilliamsR(period=14)`,
  `bt.indicators.Momentum(period=14)`, `bt.indicators.ATR(period=14)`.
- **Opposite-signal exit** — spec: *"Close an open position when an opposite entry
  signal occurs"*. All three issue `self.close()` on the opposite signal, no
  same-bar reversal (D4a canonical: at most one position, no pyramiding).
- **ATR stop** — spec: *"stop = entry_price - atr_mult * ATR"* (long) /
  *"entry_price + atr_mult * ATR"* (short), *"static from entry (default)"* with a
  trailing option *"via a parameter"*. All three: static stop from executed entry
  price and fill-bar ATR, checked intrabar against `low` (long) / `high` (short),
  exit via `self.close()` (fills next bar open); trailing mode behind a
  default-False parameter.
- **Sizing** — unstated in spec; all three use plain `self.buy()`/`self.sell()`
  (D4a canonical default sizer; tape sizes are 1.0).

Implementation-detail differences that provably do not affect the tape:

- Stop initialization: refs 0/1 set `stop_price` in `notify_order` from
  `order.executed.price` and `self.atr[0]`; ref2 sets it on the first `next()`
  in-position from `self.position.price` and `self.atr[0]`. Both read the same
  fill-bar ATR and the same fill price, so levels coincide (confirmed by identical
  tapes).
- Stop-vs-signal precedence: refs 0/1 check the stop first; ref2 uses a single
  `or`. Both paths issue the same `self.close()` on the same bar, so the fill
  (timestamp, side) is identical either way.
- Trailing-mode semantics differ across refs (ref0/ref2: close-anchored ratchet;
  ref1: entry-anchored ATR refresh, no ratchet) — **dead code** under the
  spec-pinned default *"static from entry (default)"* (`trailing=False` in all
  three).

## Pinned spec text supporting determinacy

The entry triggers are operationally pinned to the bar (*"previous bar <= -80 and
current bar > -80"*), all three indicator periods are pinned (*"period=14"* thrice),
the exit rule is pinned (*"Close an open position when an opposite entry signal
occurs"*), and the stop's default mode is pinned (*"static from entry (default)"*).

## Fragility caveat (recorded, does not change the verdict under D4)

The one unpinned spec-level choice is the stop multiple: *"an adjustable multiple
(atr_mult)"* — named but never given a value. All three refs independently listed
this in ASSUMPTIONS and independently chose **atr_mult = 2.0** ("common /
conventional default"). An instrumented sensitivity run (ref0 code, frozen cache)
shows the stop is live and the tape depends on this choice:

| atr_mult | fills | first divergence vs canonical |
|----------|-------|-------------------------------|
| 2.0 (all refs) | 90 | — (canonical) |
| 1.5 | 100 | fill 11: 2026-04-22T18:45 SELL → 2026-04-22T17:20 SELL |
| 3.0 | 84 | fill 5: 2026-04-17T13:30 SELL → 2026-04-20T16:40 SELL |
| 1e9 (stop disabled) | 49 | fill 5 (same) |

So roughly half the canonical fills are downstream of stop exits at 2.0. The
D4 classification rule is outcome-based ("all surviving faithful implementations
produce identical primary-key tapes" → DETERMINATE) and the k=3 cross-model sample
converged exactly, so the verdict is DETERMINATE. But the convergence rests on a
shared convention (2.0), not on spec text; the static screen predicted
INDETERMINATE for exactly this reason. **Metric-2 interpretation caveat:** a
candidate that faithfully implements everything but picks atr_mult = 1.5 or 3.0
would tape-mismatch the canonical reference; if their judge passes it, it counts
as a false-pass even though the spec licensed the choice. Flagged for the report's
threats-to-validity discussion.
