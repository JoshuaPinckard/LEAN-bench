# Adjudication — Task 311 (medium, AAPL 5m, "SMA(20) cross entries + 3×ATR(14) ratcheting trailing stop, long & short")

**Verdict: INDETERMINATE**
**Ambiguity classes:** `unpinned-exit`
**Repair candidates:** two (ref0 and ref1 share the same pending-order-guard defect, see below) — recorded and **empirically executed by the adjudicator**: the repair converges ref0 and ref1 exactly with each other (528-fill tapes, identical primary key) but provably cannot converge them with ref2, because the residual divergence sits on a spec sentence that explicitly licenses both mechanisms. Classification is therefore INDETERMINATE, not NEEDS-REPAIR.

## Task text (pinned vs unpinned)

> "…trading both long and short with one position at a time (no pyramiding). Indicators: SMA(20) on close, ATR(14). Entries: if flat, enter long at the next bar open when the prior bar close crosses above SMA(20); enter short when the prior bar close crosses below SMA(20). Exits: close the long when close crosses below SMA(20) OR when a ratcheting trailing stop is hit, where trailing stop distance = 3 * ATR(14). For long: trail_stop = max(previous_trail_stop, highest_close_since_entry - 3*ATR); for short: trail_stop = min(previous_trail_stop, lowest_close_since_entry + 3*ATR). **Execute stop exits as stop orders updated each bar (or equivalent logic in next()).** Ensure the trailing stop only moves in the trade's favor. Use default sizer (e.g., fixed size) and include commission/slippage placeholders."

Pinned: indicator params (SMA 20, ATR 14, 3×), entry rule and timing ("at the next bar open when the prior bar close crosses"), the trail ratchet formulas, sizing ("Use default sizer"), asset/timeframe (prose AAPL 5m == bound `AAPL_5m.pkl`, 4680 bars 2026-04-15..2026-07-10). Unpinned — and this is the decisive gap — the **exit execution mechanism**, which the spec itself leaves as an explicit disjunction: *"Execute stop exits as stop orders updated each bar **(or equivalent logic in next())**."* A resting stop order triggers **intrabar** on a high/low touch and fills at the trigger bar (at the stop price, or at the open on a gap); the "equivalent" `next()` check triggers only on a **close** beyond the trail and its market close fills at the **next bar's open**. The two spec-licensed readings produce different `(timestamp, side)` fills whenever a bar's range (or an overnight gap) crosses the trail without/before the close confirming it. Secondary unpinned points that did **not** drive divergence here: the short SMA-cross exit is never stated (the exit sentence covers only the long — all three refs independently assumed the mirror, cross-above closes the short, and declared it in ASSUMPTIONS), and the seed of `highest/lowest_close_since_entry` (all three seeded from the entry bar's close).

## Instrumented findings (run against frozen `AAPL_5m.pkl` via the tape_exec stack)

**(a) The 1/2-vs-494 "250× activity difference" is NOT a spec gap — it is one shared implementation bug in both opus refs.** Both ref0 and ref1 reset their pending-order guard by object identity (`if order is self.order: self.order = None`) in `notify_order`. Backtrader's `BackBroker.notify` delivers **clones** of orders, so the identity test is false on every notification and the guard never clears (instrumentation: entry fill 04-15 17:30, `Completed`, `order is self.order == False`; the stale order remains referenced with status `Completed` on all 4650 remaining bars).
- **ref0** checks `if self.order: return` at the top of `next()`: after the entry fill it is blocked on every subsequent bar — it never places a single trailing-stop order, never exits the short while AAPL runs 264→314 against it, and never re-enters. 1 fill.
- **ref1** checks the guard only in its flat branch, so its first trade is managed correctly (stops cancel/replaced 266.45→265.69; SMA cross-above at 18:05 → market cover fills 18:10). Once flat, the stale `Completed` entry order blocks the entry branch forever. 2 fills.

**(b) The one repair round (D4a: "pending-order guard reset in notify_order" is a canonical default; divergence on it is implementation error) was applied by the adjudicator: identity test → `order.ref` comparison, nothing else touched.** Result: repaired ref0 and repaired ref1 produce **exactly identical 528-fill (264-trade) primary-key tapes** — the two independent stop-order implementations converge perfectly once the guard bug is gone. Repaired tapes saved in the adjudication scratch run (`repaired_runs_311.json`).

**(c) Repaired refs 0/1 still diverge from ref2, and the first divergence is a textbook instance of the unpinned mechanism.** Tapes agree on fills 0–10, first divergence at fill index 11: a short entered 04-16 15:20 EDT is held overnight; on 04-17 the market gaps up through the trail level.
- Repaired refs 0/1: the **resting buy-stop** is gapped through — the 09:30 bar opens at 267.098 ≥ stop, so the stop fills at the trigger bar's open → tape `(2026-04-17T13:30:00, BUY)` @ 267.098.
- ref2: the `next()` check sees close (268.41) ≥ trail at the 09:30 bar, submits a market close, fills at the **09:35 open** → tape `(2026-04-17T13:35:00, BUY)` @ 268.394.
Same economic event, different `(timestamp, side)` key; from there re-entry alignment drifts and the tapes end at 528 vs 494 fills. Neither side can be repaired: the spec sentence *"as stop orders updated each bar (or equivalent logic in next())"* names both mechanisms as acceptable, so no explicit spec text contradicts either implementation.

## Classification reasoning (D4)

- Defect (a) **is** contradicted by explicit spec text — "Entries: **if flat**, enter long at the next bar open when the prior bar close crosses above SMA(20); enter short when the prior bar close crosses below SMA(20)": both opus refs sat through hundreds of qualifying crosses without entering (ref0 additionally violates "Exits: close the long when close crosses below SMA(20) OR when a ratcheting trailing stop is hit" and "Execute stop exits as stop orders updated each bar" — it never placed a stop nor exited at all). Both get the one repair round; both repairs verified.
- After repair, three faithful implementations survive: repaired ref0 = repaired ref1 (stop orders, 528 fills) vs ref2 (`next()` logic, 494 fills). The surviving divergence traces exactly to the quoted disjunctive clause — an unpinned spec choice the spec itself advertises. Per D4, divergence traceable to an unpinned spec choice ⇒ **INDETERMINATE**.
- The convergent pair is same-model (opus×2); the cross-model implementation took the other licensed branch — the weaker evidence form under D4a, and here the branch choice is the whole divergence.
- The static screen predicted this outcome and this class (`unpinned-exit`, citing the same sentence).

**Ambiguity class:** `unpinned-exit` — the exit execution mechanism is explicitly disjunctive in the spec ("stop orders updated each bar (or equivalent logic in next())"), and intrabar-stop vs close-checked-next-open semantics yield different primary-key tapes on this data (first at 2026-04-17 09:30 EDT, an overnight gap through the trail). The unstated short SMA-cross exit and trail-seed choice are additional unpinned points but did not drive the observed divergence (all refs made identical assumptions).

No canonical tape is written for this task.
