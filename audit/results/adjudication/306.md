# Task 306 — Adjudication

**Verdict: INDETERMINATE**
**Ambiguity classes:** `other` (spec-mandated dependency not runnable in bench environment), `unpinned-indicator-params`, `unpinned-entry-trigger`, `unpinned-exit`, `unpinned-sizing`
**Confidence:** high
**Repair candidates:** none (no ref contradicts explicit spec text; a "repair" would require contradicting it)

## Task (hard, AAPL 5m, binding coherent)

The spec demands, verbatim:

> "Add regime detection via a 2-state Gaussian HMM (**using hmmlearn**) trained on a rolling window of the last 390 bars of log returns (close-to-close)."

and makes the HMM signal load-bearing for every entry and exit:

> "go long when MACD crosses above its signal AND on the same bar the inferred HMM state transitions into the bull state; go short when MACD crosses below its signal AND on the same bar the inferred HMM state transitions into the bear state. Exit rules: close long when an opposite confirmation occurs (MACD cross down AND HMM transitions to bear); close short when MACD cross up AND HMM transitions to bull."

## Empirical outcome (convergence test)

All three references (opus x2, sonnet x1) independently and faithfully implemented the
mandated method — each contains `from hmmlearn.hmm import GaussianHMM` — and all three
crashed identically at import:

| ref | model | success | error |
|---|---|---|---|
| 0 | opus | False | `ModuleNotFoundError: No module named 'hmmlearn'` |
| 1 | opus | False | `ModuleNotFoundError: No module named 'hmmlearn'` |
| 2 | sonnet | False | `ModuleNotFoundError: No module named 'hmmlearn'` |

Verified directly against the bench python environment: `python -c "import hmmlearn"`
raises `ModuleNotFoundError`; backtrader and numpy import fine. The reference prompt's
environment facts declare "Imports allowed: backtrader, math, collections, statistics"
(ref_impl_prompt.txt line 7), and the bench's own generation-side whitelist is 8
indicators — nothing HMM-shaped. The spec's stated method is therefore not implementable
in the bench environment at all. All three refs flagged this in their ASSUMPTIONS
(ref0 topic `infeasible`: "Imported hmmlearn.GaussianHMM and numpy despite the harness
listing only backtrader/math/collections/statistics as allowed imports... this fails to
run only if those libraries are absent from the environment"; ref1 topic `dependencies`;
ref2 topic `numpy_import`) yet correctly prioritized spec fidelity per D6.

## Why not NEEDS-REPAIR

D4's rule: a divergence is an implementation error only if **explicit spec text
contradicts the implementation**. Here the opposite holds — every implementation obeys
the explicit spec text "using hmmlearn"; the environment contradicts the spec. The only
"repair" that would make the code run (substituting a hand-rolled regime detector or
dropping the HMM) would itself contradict the quoted sentence, so no legitimate repair
round exists.

## Why not DETERMINATE-EMPTY

DETERMINATE-EMPTY requires implementations that **converge on a zero-trade tape** —
i.e., they run and the spec is unsatisfiable on the bound data. These do not run: they
die at import before a single bar is processed. A crash trace is not a zero-trade trace;
"never loads" is not "never trades." There is no runnable faithful implementation whose
empty tape could be canonized.

## Why INDETERMINATE even hypothetically (secondary, spec-level gaps)

Even in an environment where hmmlearn existed, the spec does not pin a unique tape,
because the HMM fit itself is left stochastic and the decode method unstated:

- `unpinned-indicator-params`: the spec says only "2-state Gaussian HMM" — no random
  seed, covariance type, or EM iteration count. All three refs had to invent
  `random_state=42, n_iter=100, covariance_type='diag'` (ref0 `hmm-reproducibility`,
  ref1 `hmm_hyperparameters`, ref2 `hmm_random_state`/`hmm_covariance_type`/`hmm_n_iter`)
  purely to make their own runs reproducible; nothing in the spec makes different
  choices unfaithful, and EM with different seeds yields different regime sequences,
  hence different tapes.
- `unpinned-entry-trigger`: "for each bar infer the current hidden state" names no
  inference algorithm (Viterbi vs posterior argmax — ref1/ref2 chose Viterbi explicitly)
  and no inference window; "transitions into" is undefined at the daily refit boundary —
  ref2 resets the logical state at each refit so "no HMM state transition is detected on
  the session-open bar itself" (`state_reset_at_refit`), a choice refs 0/1 do not make.
  These directly gate entries.
- `unpinned-exit`: "stop distance = ATR(14) * k ... stop orders updated each bar" names
  a distance but no anchor price; all three independently guessed the current close
  (ref0 `stop-reference-price`, ref1 `stop_reference`, ref2 `stop_anchor_price`) — a
  convention, not a spec pin (entry price or trailing extreme are equally faithful).
- `unpinned-sizing`: the spec is an explicit disjunction — "position size fixed (e.g.,
  1 share) or percent-of-equity sizing" — which changes the secondary key and, via cash
  constraints, potentially the primary tape under percent-of-equity.

## Per-ref summary

- **ref0 (opus):** faithful; trains on 390 returns ending at the previous bar, infers on
  window including current bar; close-anchored stop; 1 share. Crashed at import.
- **ref1 (opus):** faithful; Viterbi decode over last 390 returns; label-based (not
  index-based) transition definition; prenext return accumulation; close-anchored stop;
  1 share; no same-bar reversal. Crashed at import.
- **ref2 (sonnet):** faithful; Viterbi decode; state reset at each daily refit (no
  transition detectable on session-open bar); close-anchored stop; 1 share. Crashed at
  import.

## Consequences

Counts against metric 1 (not determinate). No canonical tape exists; task 306 is
excluded from metric 2. Side finding per D6: no whitelist-compliant faithful
implementation exists — the task is unsatisfiable under the bench's own generation
rules and under its own execution environment.
