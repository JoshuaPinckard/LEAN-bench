## Task summary

Single-asset (bound: AAPL 1d) periodic rebalancing: hold 100% weight, force a full
close + immediate re-open every 12 weeks, exit at 52 weeks, 0.1% commission per
trade. Evaluation: "Select 50 random start dates with an available 52-week forward
horizon; for each date, run a separate backtest" and "report the average values of
the metrics across all 50 runs" (total return, max drawdown, Sharpe).

## Where the tapes diverge and why

### 1. The 50-run Monte-Carlo protocol has no single-tape reading (`other`, `unpinned-entry-trigger`) — explains ref2 vs refs 0/1

The spec's testing layer — *"Select 50 random start dates with an available
52-week forward horizon; for each date, run a separate backtest"* and *"report the
average values of the metrics across all 50 runs"* — cannot be expressed as one
`bt.Strategy` in the bench's single-backtest, single-feed harness. All three refs
declared this infeasibility in their ASSUMPTIONS and resolved it differently:

- **ref0 / ref1**: drop the 50-run protocol; implement one deterministic 52-week
  campaign with real broker orders, starting at the first available bar
  ("infeasible" assumption in both).
- **ref2**: preserve the protocol; collect closes in `next()`, resample to ISO
  weeks, and simulate all 50 runs (seed 42) arithmetically in `stop()` — **placing
  zero broker orders**, hence an empty tape.

Both are defensible literal readings; no spec sentence says orders must flow
through the backtest broker in a single pass. The entry trigger itself — *"On the
selected start date, buy the asset with 100% of the portfolio"* — is unpinned
because the start dates are *"50 random"* with no seed: refs 0/1 chose the first
bar, ref2 sampled with `random.seed(42)`.

### 2. "Weekly" schedule on a daily feed that cannot be resampled (`timeframe-mismatch`) — explains ref0 vs ref1 fill dates

*"Working timeframe — weekly (resampling from daily data if needed)"*, but the
bound data is AAPL **1d** through the bench's fixed single `PandasData` feed; a
strategy-only deliverable cannot call `cerebro.resampledata`. Each ref
reconstructed "12 weeks" / "52 weeks" differently:

- ref0: count **ISO-week boundary crossings** (`date.isocalendar()[:2]`) → first
  rebalance sell fills **2020-03-24**, 52-week exit **2020-12-29**.
- ref1: count **calendar weeks as `(dt − start).days // 7`** → first rebalance
  sell fills **2020-03-27**, exit **2021-01-04**.
- ref2: resample to the **last daily close of each ISO week** and index weeks
  0..52 within its simulation.

Every rebalance/exit timestamp difference between ref0 and ref1 traces to this
choice (plus item 3 below).

### 3. Executable meaning of "100% of the current portfolio value" (`unpinned-sizing`) — explains ref0's missing re-entries

*"Every 12 weeks, fully close the position and immediately buy again with 100% of
the current portfolio value."* Under the bench's next-open market fills plus 0.1%
commission, a literal 100% buy is not reliably executable:

- ref0 uses `order_target_percent(1.0)` (the literal reading). Its week-12/24/36
  re-entry buys were **margin-rejected** (next-open gap + commission exceed cash
  during the volatile 2020 window), leaving the tape flat from 2020-03-24 to
  2020-12-02; only the week-48 retry filled. The code faithfully attempts the
  re-buy at every scheduled point; the emptiness is broker mechanics, not a rule
  omission.
- ref1 anticipates this and sizes buys at `target_pct = 0.99` with
  `value/(price·(1+comm))` headroom, so every leg fills (complete 10-fill tape).
- Additionally, "immediately" is undefined at daily-bar granularity: ref0 re-opens
  on the bar **after** the close fill (to avoid backtrader same-bar netting and
  margin risk); ref1 submits close + buy on the **same** bar.

The spec pins the nominal weight (100%) but not its operationalization under the
bench's fill/commission mechanics; both readings are defensible, so this is
unpinned, not an implementation error.

## Repair analysis

Strict rule: repair only where an explicit spec sentence unambiguously contradicts
the code.

- **ref0**: targets literal 100%, rebalances every 12 counted weeks, exits at 52.
  No contradicted sentence. The sparse tape is an emergent artifact of the literal
  reading. No repair.
- **ref1**: buys 99% rather than 100%. The sentence *"buy the asset with 100% of
  the portfolio"* is not an unambiguous contradiction: literal 100% is not
  executably achievable under next-open fills + commission (ref0 demonstrates it
  margin-rejects), so a headroom-sized "essentially fully invested" position is a
  defensible operationalization of an unexecutable pin, declared in ASSUMPTIONS.
  Even if repaired to literal 1.0, ref1's `days // 7` week counting would still
  diverge from ref0's ISO-week crossings, and ref2 would still be empty — repair
  cannot rescue convergence. No repair.
- **ref2**: places no broker orders, but the spec nowhere states that trades must
  be executed through the backtest engine in a single pass, and its choice is the
  only one of the three that preserves the explicitly specified 50-run averaging
  protocol. (Their bench's own ≥1-trade gate would reject it, but that is a gate,
  not spec text.) No repair.

`repair_candidates`: **empty** — all divergence traces to unpinned spec-level
choices, none to explicit-text violations.
