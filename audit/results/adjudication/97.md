## Finding 1 — a shared implementation defect corrupts all three tapes (repair candidates: ref0, ref1, ref2)

All three refs place their stop-loss/take-profit orders inside `notify_order` behind an **object-identity check** against the stored entry order (`if order is self.entry_order:` in ref0/ref2, `if order is self.order:` in ref1). But this stack's broker notifies **clones**:

```python
# backtrader/brokers/bbroker.py (installed version)
def notify(self, order):
    self.notifs.append(order.clone())
```

so the identity test is never true. Verified empirically by re-running each ref through the frozen cache with an order-log analyzer (`scratchpad/debug97.py`, `debug97b.py`): **no Stop or Limit order is ever submitted by any ref** — the SL/TP placement code is dead — and the pending-order guards (`entry_order` / `order` / `close_order`) are **never reset**, freezing each strategy after its first order cycle.

Tape-relevance of the dead SL/TP code (checked against the frozen AAPL bars):

- **ref0/ref1 (long, entry fill 2020-02-03 @ 73.285):** TP level = 75.4837. 2020-02-04 opened at 75.94 (high 76.98) — a live take-profit limit **would have sold on 2020-02-04**. Instead ref0 exits 2020-02-24 via the crossover market order, and ref1 never exits at all. This contradicts explicit spec text: *"Take-profit for a long position: Set at 3% above the entry price."* and *"Stop-loss for a long position: Set at 2% below the entry price."*
- **ref1 additionally** contradicts *"Closing a long position (Sell): When the next day's closing price crosses the forecast EMA (`EMA_forecast(N+1)`) from above to below."* — its crossover math is algebraically identical to ref0's (which fired on the 2020-02-21 signal bar), but ref1's `if self.order is not None: return` guard at the top of `next()` is never released (clone identity), so the exit branch is unreachable. Ref1 holds the 2020-02-03 long through 2025-12-30 with no stop-loss through the COVID crash.
- **ref2 (short, entry fill 2020-04-07 @ 65.372):** TP level = 63.411. 2020-04-08 low = 63.06 — a live take-profit buy-limit **would have covered on 2020-04-08**. Instead the short covers 2020-04-23 via crossover. Contradicts: *"Take-profit for a short position: Set at 3% below the entry price."*
- In ref0 and ref2 the never-cleared guards additionally freeze the strategy after its first round trip (`_has_pending()` / `entry_order is None` false forever), suppressing every subsequent entry over the remaining ~5.7 years — a repaired ref0 produces 795 fills vs the shipped 2.

Per D4/D4a this is **implementation error, not spec ambiguity** (D4a explicitly makes "pending-order guard reset in `notify_order`" a bench-canonical default; misimplementing the reset against clone semantics is a code bug). All three refs are repair candidates. Note for the report: this identity-vs-clone trap was hit independently by 3/3 models (opus ×2, sonnet ×1) — likely endemic in candidate code too.

## Finding 2 — even after repair the divergence traces to unpinned spec choices → INDETERMINATE

A diagnostic repair (delivering notifications to the original order objects, `scratchpad/debug97c.py` / `debug97d.py`) shows repairs **cannot** produce convergence:

1. **`unpinned-entry-trigger` — the optional EMA(50) trend filter.** Spec: *"To filter false signals, an additional condition **can be added**: trades are allowed only in the direction of the main trend, determined by EMA(50). For example, to open a long position, EMA(50) must be trending upward."* Ref0 and ref1 read "can be added" as optional and omitted it (both say so in ASSUMPTIONS); ref2 included it. Inclusion changes everything: the EMA(50) indicator raises backtrader's minperiod to 50, so ref2 cannot trade before mid-March 2020 (ref0/1 enter 2020-02-03), and the filter gates entry direction thereafter (ref2's first trade is a 2020-04-07 short). Within the filter, *"trending upward"* is undefined (ref2 chose a one-bar `EMA50[0] > EMA50[-1]`) and the short-side condition is entirely unstated (ref2 assumed symmetry). Repaired ref2 (99 fills, first fill 2020-04-07) remains disjoint from repaired ref0/1 (first fill 2020-02-03). Both readings are faithful; the text pins neither.
2. **`unpinned-sizing`.** Spec: *"Position size: Fixed, **for example**, 100% of available capital per trade."* Refs chose 95% (ref0), 98% (ref1), 100% (ref2) of cash — each justified in ASSUMPTIONS as a margin-rejection workaround the hedged text invites. Under the repair simulation, ref0 vs ref1 primary keys — identical in every other semantic — diverge at fill 14 (`2020-03-10 BUY` vs `2020-03-11 BUY`) and end at 795 vs 785 fills: the buffer choice alone shifts *timestamps*, not just sizes (via margin/OCO-check interaction in the March 2020 crash), so it breaks even the size-blind primary key.
3. **`unpinned-exit` (latent, code-level).** Spec: *"Closing a long position (Sell): When the next day's closing price crosses the forecast EMA (`EMA_forecast(N+1)`) from above to below."* Ref0/ref1 evaluate the cross against a **rolling forecast line** (each close vs its own prior-bar forecast: `Close[-1] > FC(t-1)` and `Close[0] < FC(t)`); ref2 evaluates both closes against the **single** prior-bar forecast level (`prev_close > pef and close < pef`). Both are defensible readings of "crosses EMA_forecast(N+1)". Not separately observable in the shipped tapes (masked by findings above), but a real fork that survives repair. Ref1's ASSUMPTIONS also flag that a fully static per-trade forecast level is a third possible reading it rejected as incoherent.

The entry threshold denominator (*"The difference between `Close(N)` and `EMA_forecast(N+1)` must be at least 0.5%"* — base unstated) was independently resolved identically by all three refs (÷ Close(N)), so it did not drive divergence; recorded as latent only.

## Per-ref summary

- **ref0 (opus):** faithful core reading (no filter, Close-based threshold, rolling-line cross exit, OCO SL/TP intended). Defect: clone-identity → SL/TP never placed, strategy frozen after 2020-02-24. Repair candidate (TP/SL sentences).
- **ref1 (opus):** semantically identical to ref0 except 98% sizing buffer. Same defect, worse manifestation: global pending-order guard never released → no exit ever. Repair candidate (TP/SL sentences + long-exit sentence).
- **ref2 (sonnet):** faithful alternate reading (filter included). Same clone-identity defect → SL/TP never placed, frozen after 2020-04-23. Repair candidate (short-TP sentence).

## Decision

Divergence is **mixed**: ref-internal implementation error (Finding 1, all three refs listed in `repair_candidates`) *and* genuine spec ambiguity (Finding 2). Since the ref0/1-vs-ref2 fork (optional filter) and the ref0-vs-ref1 post-repair fork (sizing buffer) trace to quoted unpinned text, no repair round can yield a unique tape. **INDETERMINATE** — `unpinned-entry-trigger`, `unpinned-sizing`, `unpinned-exit`. No tape is canonized. Matches the static screen's prediction (`results/screen/97.json`).
