## Where the surviving refs diverge, and why

### 1. The signal generator itself — `unpinned-entry-trigger`, `unpinned-indicator-params` (primary cause)

The spec's entire entry logic is: *"Implement logic based on an LSTM model that analyzes data sequences and predicts the next action: BUY, SELL, or HOLD"*, driven by *"a set of 62 independent features"* of which the only named ones are circular (*"features reflecting the imbalance between BUY, SELL, and HOLD signals"*). No trained weights, no architecture, no feature list, no decision boundary is given, and an LSTM cannot be trained or executed in the bench's backtrader-only, single-OHLCV-feed environment at all. Every faithful implementation is therefore forced to invent a deterministic proxy, and each ref invented a different one:

- **ref0** (`_predict`): 24-bar price momentum `(close[0]-close[-24])/close[-24]` with a ±0.002 return dead-band for HOLD.
- **ref1** (`_predict_signal`): count of up vs down bar-to-bar moves over the last 20 bars; `|up-down|/20 >= 0.2` triggers BUY/SELL, else HOLD.
- **ref2** (crashed): a 10-indicator all-conditions ensemble (EMA 9/21/50, MACD, RSI, Bollinger, Stochastic, Momentum, WilliamsR + signal-imbalance fractions) — a third, again different, proxy.

Both surviving refs declared this substitution explicitly under `ASSUMPTIONS` (`topic: infeasible` / `lstm_proxy`). Since the entry trigger decides every fill, this gap alone fully explains the disjoint tapes (ref0's first trade is a SELL on 02-21; ref1's is a BUY on 02-19). The proxy windows and thresholds (24/0.002 vs 20/0.2) are likewise invented parameters — `unpinned-indicator-params`.

### 2. Sizing affordability — `unpinned-sizing` (secondary, independently divergent)

Spec: *"The size of each position must be calculated automatically depending on the current account capital, so that the risk per trade is a fixed percentage of equity (e.g., 1-2%)."* Both refs picked 1% (from the "e.g." range — itself unpinned), and both compute `size = risk_amount / stop_distance`. But on a $10,000 account trading ~$2,000+ gold bars, the risk-based size routinely exceeds what cash can fund:

- **ref0** submits the uncapped risk-based size (its first fill is a 21-unit short, ~$42k notional; long entries of that size can be margin-rejected by backtrader's broker while shorts fill).
- **ref1** caps the size at `0.99 * cash / price` (declared as `topic: size cap`), so its orders fill at affordable sizes in both directions.

The spec says nothing about what to do when the risk-mandated size is unfundable, so both readings are faithful; they produce different fill sequences.

### 3. Exit machinery — `unpinned-exit` (unpinned in text, coincidentally converged here)

*"Stop Loss must be set automatically based on calculated volatility"* names no volatility measure, period, or multiplier; *"Take Profit must be set automatically based on the specified Risk/Reward ratio (e.g., 1:2 or 1:3...)"* offers explicit alternatives; the trailing rule (*"Stop Loss must be moved automatically (trailed) following the price"*) gives no trail formula. Ref0 and ref1 happened to converge on ATR(14)×1.5, R/R 2.0, and a tighten-only trail to `close ∓ 1.5×ATR` — convention, not spec pinning; a third faithful implementation could legitimately choose ATR(20)×2, 1:3, or a high-water trail and remain compliant. The daily-risk (*"e.g., 2% of the deposit"*), drawdown (*"e.g., 5% of the deposit"*) thresholds and the *"reset to zero every 24 hours"* boundary are equally example-valued; both refs adopted the examples and a calendar-day reset.

### 4. External data — `external-data-required`

*"all open positions must be closed automatically 30 minutes before the start of the release of highly volatile economic news"* requires an economic calendar that does not exist in the OHLCV feed. Both refs shipped it as a permanently-disabled no-op flag (declared infeasible). It did not cause divergence here but is unimplementable as specified.
