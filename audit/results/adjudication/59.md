## Ref2 crash — implementation bug, excluded

Error: `Backtest error: MACD.__init__() got an unexpected keyword argument 'period1'`.
Ref2's code instantiates `bt.indicators.MACD(self.data.close, period1=12, period2=26, period9=9)`;
backtrader's MACD takes `period_me1`, `period_me2`, `period_signal` (and `period9` is not a
plausible kwarg under any API). Both opus refs instantiated MACD correctly with the same
(12, 26, 9) values, so the spec sentence "MACD: with default settings (fast EMA 12, slow
EMA 26, signal SMA 9)" is implementable as written — the crash reveals nothing about the
spec. Notably the MACD is dead code in all three refs (see below), so the bug is in an
indicator ref2's own signal logic never reads. Excluded as implementation error; no repair
needed because two faithful implementations already survive and converge (D4 requires ≥2).

## Genuineness of convergence

Ref0 and ref1 are structurally independent implementations, not copies of one shortcut:

- **Window aggregation:** both bucket 5-minute bars into clock-aligned 30-minute windows
  and finalize a window at the first bar of the next one, but ref0 keeps running
  sums/counters while ref1 keeps a per-window RSI list plus a monotonic `bucket_id`.
- **Entry filter:** both require a *complete* 6-bar window with `ma_crosses == 1` and
  `avg_rsi > 70`, where crosses come from `bt.ind.CrossOver(SMA13, SMA40) > 0` on the
  5-minute feed and avg_rsi is the mean of the six 5-minute RSI(14) values. This shared
  reading is pinned by the spec's own condition definitions: `ma_crosses` is "The number of
  times the fast SMA(13) crossed the slow SMA(40) **upward** during these 30 minutes
  (**based on 5-minute data**)" and `avg_rsi` is "The average value of the RSI indicator
  over the 30-minute period" — an average over the window only exists if RSI is computed on
  the 5-minute bars. The screen's worry that "aggregate the data into 30-minute candles"
  could instead mean recomputing indicators on 30m OHLC is overridden by these explicit
  per-condition definitions, and both refs cite exactly this text in their ASSUMPTIONS.
- **Holding-period exit** ("Close the position after **6** 30-minute periods following its
  opening"): ref0 increments a counter at each window finalization and closes at ≥6;
  ref1 records `entry_bucket_id` at fill and closes when `bucket_id - entry_bucket_id >= 6`,
  checked every bar. Different mechanisms, same behavior: all 7 exits fill exactly 3h after
  entry (17:05 vs 14:05).
- **Stop-loss / take-profit — genuinely divergent unpinned choices that still converged:**
  ref0 evaluates SL/TP on each 5-minute bar's *close*; ref1 evaluates intrabar against the
  bar's *low/high*. On the bound AAPL 5m data neither branch ever fired: every exit is the
  timed 6-window close, and per-trade close-to-close returns span only −0.75%…+1.41%,
  inside the −1.5%/+3.0% band. So the most tape-relevant ambiguity was empirically tested
  (the two refs chose differently) and proved inert on the bound data.
- **MACD:** both instantiate MACD(12,26,9) but never reference it — correctly, since the
  spec's "Signal generation logic" names only `ma_crosses` and `avg_rsi`; both ASSUMPTIONS
  lists state that adding a MACD condition would invent an unspecified filter.
- **Sizing:** the spec hedges — "Use a fixed position size, **for example, 100% of
  available capital per trade**." Both refs chose `int(cash * 0.99 / close)`. This is the
  one unpinned choice where the survivors agreed by convention rather than by spec text;
  it only touches the primary key through potential margin rejections, none of which
  occurred. Recorded as a fragility, not a divergence.
- **Infeasible clauses:** both refs note the "30–50 liquid tickers" and "past several
  years" requirements are unsatisfiable under the D2 binding (single AAPL 5m feed,
  ~3 months) and implement on the bound feed per D2. This is a reportable binding finding,
  not an ambiguity that produced divergence.

## Rule application

Per D4, classification is empirical: "**DETERMINATE** — all surviving (≥2) faithful
implementations produce identical primary-key tapes." Two survivors, identical tapes,
independently structured code, with the key unpinned choice (SL/TP mechanics) actually
differing between them and still converging. Verdict DETERMINATE; canonical tape = ref0.

**Caveats (why confidence is medium, not high):** both survivors are the same model (opus);
the D4a cross-model leg (sonnet) was lost to an API crash. The static screen predicted
INDETERMINATE (`unpinned-entry-trigger`, `unpinned-exit`, `unpinned-sizing`,
`multi-asset-required`); the entry-trigger worry is answered by explicit spec text, the
exit worry was tested-and-inert on the bound data, and the sizing worry went untested
because both survivors picked the same convention. The determinacy claim is therefore
solid under the pre-registered rule but rests partly on the bound data keeping the SL/TP
branch inert.

**repair_candidates:** none. Ref2's crash contradicts no spec sentence (its MACD parameter
*values* matched the spec; the kwarg names were a backtrader API error), and no surviving
ref's tape diverges.
