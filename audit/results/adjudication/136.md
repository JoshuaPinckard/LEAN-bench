## Where the tapes diverge and which spec gap explains each difference

### 1. The trailing-stop definition — the biggest unpinned lever → `unpinned-exit` + `unpinned-sizing`

Spec:

> "use a trailing stop that follows the price, **lagging by a distance equal to the value of the 8-period EMA**. This means that the stop-loss will automatically move upward as the price rises, but will not fall below its previous value."

Two faithful readings coexist:

- **Literal (ref0, ref1):** trail *distance* = the EMA value itself → stop level = close − EMA(8) ≈ $2 on a $180 stock (verified on the frozen data; min Low after entry is 163.85, so the stop never fires). Both opus refs flagged the absurdity in ASSUMPTIONS and kept the literal reading.
- **Sensible (ref2):** the stop level *is* the EMA(8) line, ratcheted upward with `max()` (ref2's ASSUMPTIONS: the literal distance "yields a stop near zero or negative—meaningless for risk management").

This same phrase also determines position size, because the sizing rule is parameterized by the stop distance:

> "Risk per trade must not exceed 2% of total trading capital. Position size is calculated so that the potential loss from the stop-loss does not exceed this limit."

Literal distance = EMA ≈ $179/share → `int(200/179)` = **1 share** (ref0, ref1). Stop-at-EMA distance = close − EMA ≈ $4/share → **49 shares** (ref2). The sizing formula is stated but its key input is unpinned, so the executed sizes differ by 49×.

### 2. ref0 vs ref1 — both faithful, both successful, different primary-key tapes → `unpinned-exit`

Both opus refs agree on the literal trailing stop, high-based TP triggers (`high >= level` for "upon reaching the price"), and the 1-share size — yet their `(timestamp, side)` sequences differ (17 vs 20 fills; ref1 has SELL 2025-10-01, 2025-10-14, 2025-11-10 … that ref0 lacks). The cause is the 50% partial on a 1-share position:

> "**Take-profit:** Close 50% of the position upon reaching the price 184.89."

- ref1 sells a **fractional 0.5 share** (backtrader permits it): first TP1 fill 2025-10-01 (trigger 2025-09-30, the first bar with High ≥ 184.89), remainder at TP2 fill 2025-10-10.
- ref0 computes `int(1 × 0.5) = 0`, **skips the partial** (marks it taken), and exits the full share at TP2 → single SELL 2025-10-10 (trigger 2025-10-09, first High ≥ 192.95).

The spec never says whether fractional shares exist or how "50%" rounds on an odd/1-share position — a gap created by the spec's own sizing rule, which (under the literal stop reading) forces a 1-share position on $10,000 cash. Downstream, the different exit cadence shifts every subsequent re-entry (ref0 BUY 2025-11-03 vs ref1 BUY 2025-11-04, etc.). A related unpinned choice both refs flagged: same-bar exit priority (ref0 checks TP2 unconditionally before TP1; ref1 gates TP2 on TP1-done) — the spec is silent on ordering when one order per bar is possible.

### 3. ref2 vs ref0/ref1 — trigger basis → `unpinned-exit` (would persist after repair)

"Upon reaching the price 184.89 / 192.95" is evaluated intrabar (`high >= level`) by ref0/ref1 but on close (`close >= level`) by ref2 (ASSUMPTIONS: "On daily bars an exact float equality hit is practically impossible; >= is the standard interpretation"). Neither basis is quoted anywhere in the spec (contrast: entry explicitly says "closing price of the current bar exceeds the level 179.33"). Even with ref2's bug repaired, this choice plus §1 keeps its tape distinct.

## Repair analysis (strict standard)

### ref2 — CONFIRMED implementation error, listed in repair_candidates

Ref2's tape is a single BUY of 49 shares on 2025-08-05 held untouched to the end of data (2025-12-30). On the frozen NVDA data, after that entry there are **32 bars with Close ≥ 184.89** (first: 2025-09-30) and **9 bars with Close ≥ 192.95** (first: 2025-10-28; Close max 206.78). Under *any* reading of the trigger basis — including ref2's own declared `close >= level` — the spec's explicit sentences:

> "**Take-profit:** Close 50% of the position upon reaching the price 184.89."
> "**Final take-profit:** Close the remaining part of the position upon reaching the price 192.95."

are contradicted by a code that never closes any part of the position. Root cause (reproduced by re-running the ref through `tape_exec.py` and instrumenting): in the bench's backtrader version, `notify_order` delivers **cloned** order objects (verified: Submitted/Accepted/Completed notifications each arrive with a different object id than the one `self.buy()` returned), so ref2's guard reset

```python
if order is self.order:
    self.order = None
```

never matches. `self.order` stays truthy forever; the `if self.order: return` guard at the top of `next()` blocks all exit logic from the fill bar onward. A hand simulation of ref2's *intended* logic shows its trailing stop would have exited on 2025-08-15 (close 180.21 ≤ ratcheted EMA stop 180.75). This is also a failure of the D4a canonical default ("pending-order guard reset in `notify_order`"), which D4a designates as implementation error, repairable. Ref0 and ref1 reset the guard on status alone (no identity check) and are unaffected.

### ref0, ref1 — no quotable contradiction

- ref0's skipped partial does not contradict "Close 50% of the position": 50% of 1 share is 0 whole shares; the spec pins neither fractional-share availability nor rounding.
- ref1's fractional 0.5-share sell is equally covered — backtrader accepts it and the spec doesn't forbid it.
- Both implement the trailing stop exactly as written ("distance equal to the value of the 8-period EMA"); that the literal stop is degenerate (~$2 level, never hit) is a spec defect, not a code error.
- Sizing: both apply "2% of total trading capital" with `broker.getvalue()` and the stated stop distance; no text pins a different base or distance.

### Why the verdict is INDETERMINATE rather than NEEDS-REPAIR

Not all divergence traces to explicit-text violations. Excluding ref2 (or repairing it), the two surviving faithful implementations (ref0, ref1) still produce different primary-key tapes, and that divergence traces entirely to unpinned spec choices (§1–§2: partial-close realization under spec-forced 1-share sizing; exit priority). A repaired ref2 would additionally diverge on the trailing-stop reading and trigger basis (§1, §3), both unpinned. No repair round can produce convergence, so the one-repair budget is not spent.

**Conclusion:** Task 136 is INDETERMINATE (`unpinned-exit` primary, `unpinned-sizing` secondary), with ref2 separately recorded as an explicit-text violator (broken pending-order guard) per the repair-candidate ledger. The static screen predicted INDETERMINATE/`unpinned-exit`, matching; the screen's `pinned_sizing: true` was too generous — the sizing formula is stated but keys off the unpinned stop distance, so executed sizes are not pinned (1 vs 49 shares).
